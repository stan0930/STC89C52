## 3 你举的例子 数码管显示小数和负号

### 3.1 先把数值变成段码

你的开发板电路图和现有段码表对应：P0 的 bit0～bit6 控制 a～g，bit7 控制 DP，高电平点亮。

| 想显示的内容 | 段码或操作 |
| --- | --- |
| 空白 | `0x00` |
| 数字 0 | `0x3F` |
| 数字 2 | `0x5B` |
| 负号 | `0x40`，只亮 g 段 |
| 带小数点的 2 | `0x5B | 0x80`，结果 `0xDB` |

**小数点是某一位自带的灯，不额外占一位。** 显示 `-12.3` 时，从左到右 8 位的缓冲区可以是：

```c
{0x00, 0x00, 0x00, 0x00, 0x40, 0x06, 0xDB, 0x4F}
/* 空    空    空    空      -     1     2.    3 */
```

注意 `| 0x80` 应加在 2 上，不能加在 3 上。正数默认不显示符号。普通七段数码管缺少居中竖段，无法准确画出常规“+”；若题目明确要求正号，按题目给定的近似图形或表示规则实现，不要自行认定某个段码就是标准加号。

### 3.2 用定点整数表达小数

不必先用浮点数。把数值和小数位数分开保存即可：

| 保存的整数 | 小数位数 | 应显示 |
| --- | --- | --- |
| `1234` | 2 | `12.34` |
| `-1234` | 2 | `-12.34` |
| `5` | 1 | `0.5` |
| `-5` | 1 | `-0.5` |
| `5` | 2 | `0.05` |
| `0` | 2 | `0.00` |

如果要求按键每次增加 0.1，就保存“实际值乘 10”的整数，每按一次加 1。不要反复累加浮点数再猜该点亮哪一位。

### 3.3 格式化算法

1. 把准备显示的 8 位段码先全部清为 `0x00`。
2. 记录是否为负，把数值转换成无符号的绝对值。
3. 从最右侧开始，`% 10` 取一位、`/ 10` 去掉一位。
4. 至少写出“小数位数 + 1”个数字，保证 `0.05` 的整数位 0 不会丢。
5. 拆到整数个位时，用 `| 0x80` 打开其小数点。
6. 负数在数字左侧再放 `0x40`，同时检查剩余位置。
7. 超过 8 位时明确报错或显示横线，不能继续写数组。

参考程序见 [decimal_signed_demo.c](decimal_signed_demo.c)。它有自己的 `main`，固定显示 `-12.34`，支持 0～3 位小数、负数、零和位数检查。正数不显示符号；超长或非法小数位数显示 `--------`。

核心调用：

```c
SegSetScaled(-1234L, 2);  /* -12.34 */
SegSetScaled(5L, 1);      /* 0.5 */
SegSetScaled(-5L, 1);     /* -0.5 */
SegSetScaled(0L, 2);      /* 0.00 */
```

这里只负责显示已确定的小数位，不负责四舍五入。题目要求四舍五入时，要在生成定点整数时处理。

### 3.4 显示内容和显示扫描分开

你原来的 `Int_DigitalTube_DisplayNum(u32)` 只是写显存；`Refresh()` 才把显存扫出来。考试时把这两个职责分开：

- 主循环在数值变化时重算段码。
- Timer0 每次中断只扫一位，不写任何延时。
- 8 次中断组成一帧，按当前设置约 8 ms。

你的板子：P0 段选，P1.3～P1.5 位选，P3.6 为数码管低有效使能。每次扫描顺序：

```c
P0 = 0x00;                         /* 先消隐，避免重影 */
P1 &= 0xC7;                        /* 清除旧位号，保留其他锁存位 */
P1 |= (pos << 3);                  /* 写入新位号 */
P0 = buffer[pos];
```

这里沿用原代码对 P1 做两次读改写；Keil 生成的 ANL/ORL 端口指令读取输出锁存器。不要随意改成读整口再拼接赋值，否则 IIC 从设备拉低 SDA 时，可能把外部低电平写回 P1.6 锁存器。LED、数码管、点阵共用 P0；参考程序关闭另外两个显示模块。主循环更新多位显存时，先在临时数组里算好，再短暂关中断复制，避免更新一半就被扫描；不要在整个除法格式化期间关闭中断。

原 `Int_DigitalTube_Refresh()` 内部扫 8 位并延时约 8 ms，**不能原样注册进 1 ms 定时回调**。

## 5 综合题里要记住的几个公式

### 温度保留正负号和小数

当前温度接口返回 `char`，并丢弃低 4 位，无法恢复小数。应从低字节和高字节重新组合完整补码：

```c
signed int raw;
signed int temp10;

raw = (signed int)(((unsigned int)ms_byte << 8) | ls_byte);
temp10 = (signed int)((signed long)raw * 10L / 16L);
SegSetScaled((signed long)temp10, 1);
```

这是针对默认 12 位分辨率，把温度转换为十分之一摄氏度，除法向零截断。例如 `raw = -8` 得到 `-0.5`。先转 long 再乘，防止 16 位中间乘法溢出。不要先把 `raw` 右移 4 位，否则小数已经丢失；四舍五入需求另行处理。

通信顺序是“复位、CC、44、等转换完成；复位、CC、BE、低字节、高字节”。Word 旧例漏了转换等待，你的当前代码已经补了 750 ms。

进一步练习：把“启动转换”和“到期读取”拆成两步，等待期间继续处理按键。1Wire 驱动的微秒时序还会受到中断影响；关键读写时隙如需短暂保护，要恢复原来的 EA，不能关闭总中断等待整个 750 ms。单设备时才直接用跳过 ROM 的 `0xCC`。

### BCD 和十进制

```c
bcd = (value / 10) * 16 + value % 10;
value = (bcd >> 4) * 10 + (bcd & 0x0F);
```

`0x23` 的 BCD 意义是十进制 23，不是十进制 35。校时需要检查时 0～23、分秒 0～59；设置 DS1302 前关闭写保护，写后恢复。读时间要处理 CH 等控制位。跨秒一致性有要求时，使用突发读取或读秒复核，避免读到跨时刻组合。

### EEPROM 跨页和数值拆字节

```c
page_remain = PAGE_SIZE - address % PAGE_SIZE;
/* 本次写入量取 page_remain 和剩余 len 中较小者 */

low  = (unsigned char)value;
high = (unsigned char)(value >> 8);
value = ((unsigned int)high << 8) | low;
```

以上拆字节示例用于无符号 16 位值；有符号参数要先约定其存储编码及恢复方式。页大小、写完成时间按实际芯片手册确定，不能由容量直接推断。你目前 `PAGE_SIZE=16`、页后等待 3 ms，不应不加核对地当作所有 24C02 都适用。每一页包括最后一页，都要等内部写入完成或做 ACK 轮询。只在确认保存或参数改变时写，别每次主循环都写。

## 6 当前代码中最容易影响考试的坑

1. **定时器初始化会清空回调。** 先 `Dri_Timer0_Init()`，再初始化 UART 和注册自己的任务；不要运行中反复初始化 T0。最多 4 个回调，UART 的空闲检测会占一个槽。
2. **所有 Timer0 回调都在中断里。** 只放逐位扫描、短计数和置标志。不要延时、等待松手、等待测温或发送长串口字符串。
3. **定时回调里发送字符串可能卡死。** UART 发送忙标志依赖串口中断清除，同优先级中断不能互相抢占。把发送放在主循环。
4. **数码管整数函数有越界风险。** 原版只收 u32，负数传进去会变成很大的无符号数；超过 8 位会越界写显存。要先判断符号并限制位数。
5. **普通 char 不适合直接当带符号温度。** 用 `signed int` 或 `signed long`；中间乘法也检查类型。
6. **消抖和等待松手可能阻塞其他任务。** 练熟“固定周期采样、连续稳定若干次确认、只在状态变化时生成事件”。长按连发要另加保持时间和重复周期。
7. **当前 UART 接收缓冲只有 16 字节且没有上界检查。** 自己的目标数组即使开大，也不能修复驱动内部越界；正式使用需限制发送长度或补充接收保护。16 字节内容加字符串结束符，目标至少 17 字节。
8. **两类返回值含义相反。** `Dri_IIC_ReceiveAck()` 返回 0 表示 ACK；`Dri_1Wire_Init()` 返回 1 表示检测到设备。
9. **OLED 只带 ASCII 字库。** 当前 `main.c` 使用的 `℃` 是多字节字符，不能直接用 `str[i]-32` 查 ASCII 字库；应使用 `C` 或自己做字模。
10. **当前 main 的 str[17] 装不下部分输出。** 时间、`Tmp:`、温度和 `℃` 拼在一起会超长；同时 OLED 每行只有 16 个 8 像素字符。先规划固定宽度，如 `12:34 T:-25.3C` 为 14 字符，留出结尾 0；短字符串覆盖长字符串时补空格。
11. **OLED 和 EEPROM 的头文件都定义 DEV_ADDR。** 综合使用时改用模块专属名字，避免 0x78 和 0xA0 被混用。IIC 地址要区分 7 位地址与包含读写位的总线地址字节。
12. **主程序和中断共享状态要用 volatile。** 但 volatile 不保证 16/32 位读取原子性，必要时短暂关中断读写；不要同时从主程序和 ISR 调用没有重入保护的总线或普通 C51 函数。

还有两处查 Word 时要留意：定时器中断允许位属于 IE，不是 IP；OLED“小试牛刀”部分有参数 `len`、循环却写 `count` 的笔误。查到示例后先核对变量名和结束条件再用。

## 8 限时模拟题

### 模拟一 可调小数计数器

允许查看原 Dri 和原 Word，建议限时 60 分钟。

- 显示一个范围为 -99.9～99.9 的数，初始 0.0。
- SW1 加 0.1，SW2 减 0.1，SW3 清零，SW4 切换“显示数值”和“显示按键计数”两个页面。
- 单次按键只触发一次，到达上下限后保持，不允许越界。
- 计数页面显示全局累计按键次数；本题约定 SW1～SW4 的每个有效按下事件都计入，包括切页键，页面切换不清零。
- 数值靠右，负号跟在数字前，小数点位置正确，按键时显示不闪断。

先写出状态：`value10`、`page`、`key_count`；再写事件如何修改它们。扫描函数只读显存，不处理按键业务。

验收：`0.0`、`-0.1`、`-9.9`、`-99.9`、`99.9`；切页面再返回时数值保持。

### 模拟二 温度报警与保存

建议限时 90 分钟，先完成基本分数项，再做掉电保存。

- 用 DS18B20 采温，显示一位小数，支持负温。
- 按键切换温度页与阈值页，阈值范围 0～50.0，每次调整 0.5。
- 高于阈值时蜂鸣器间歇报警；回落至“阈值减 1.0”及以下时停止，避免在临界点反复切换。
- 确认键将阈值保存 EEPROM，重启恢复；未初始化或数据无效时使用默认 30.0。
- 采温转换等待期间仍能响应按键；数码管扫描不停止。

验收：低于阈值、刚好等于阈值、略高于阈值、回落但未达到解除条件、保存后重启。没有办法制造负温时，先给格式化函数输入模拟负值，验证显示，再接入实测数据。

## 9 遇到一道新题的下笔顺序

先圈出输入、输出、周期和边界；写出需要保存的状态变量；查 Word 的基础外设流程；只选需要的 Dri；先跑通最小显示，再逐项添加事件和定时任务。最后检查端口复用、中断耗时、数据类型、数组长度、刷新是否持续。

如果只剩很少复习时间，优先做到：**不依赖现成 Int，从允许的 Dri 和 Word 出发，独立写出一个按键可调的有符号小数显示程序。** 这一个练习能同时覆盖格式化、扫描、定时器、按键和状态管理。
